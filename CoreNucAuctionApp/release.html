Reliability and Operational Safeguards

  • Automatic verified backups are created periodically and during normal application shutdown, with optional password-protected AES-256 authenticated encryption.
  • Invoices and settlements use temporary workstation locks to prevent conflicting financial changes.
  • Payments cannot exceed the current authoritative balance, and invoices cannot be finalized with an outstanding balance.
  • Refunds, adjustments, reopen actions, returns, transfers, and other corrections require reasons and preserve history.
  • Imports are previewed and validated before live records change, with rollback if a record fails.
  • Closeout identifies blockers such as unpaid invoices, open drawers, unpaid consignors, or pending synchronization.
  • Performance and memory-management improvements support longer auction sessions and larger record sets.

Packaging Notes

The Microsoft Store package is named CoreNucAuctionApp-LazyLionsEdition-1.0.0.0-x64.msix. Store builds use the registered CoreNuc Auction App identity and receive updates through Microsoft Store.

A self-contained customer setup executable and MSI are also supported for direct and managed deployment. These packages include the Windows x64 application, required .NET desktop and ASP.NET runtimes, and native SQLite runtime.

The direct-release pipeline supports Authenticode signing, trusted timestamps, signature verification, and SHA-256 manifests. Upgrades preserve the database, catalog photos, backups, and settings stored under local application data.

Known Notes

  • CoreNuc Auction App — Lazy Lions Edition is a Windows desktop application packaged for x64 computers.
  • Multi-computer synchronization is intended for a trusted private local network.
  • Each workstation must keep its own local database; do not share the SQLite database file over the network.
  • Catalog photos are copied into a local application-data folder but are not synchronized to other workstations or included in database-only backups.
  • Encrypted backup passwords must be retained securely and are required when restoring on a replacement computer.
  • For a multi-computer auction, final closeout should be performed on the host after all workstations are connected and fully synchronized.
